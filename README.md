# Проверка расстояний при обработке поля с БАС

Подготовлен исполняемый пример: три вручную формализованных фрагмента санитарных норм связываются с учебными геометрическими объектами. Расчёт возвращает расстояние, пункт источника и найденное противоречие. При неполных данных он не выдаёт благополучный результат.

## Проверяемый вывод

Порог 700 м нельзя автоматически распространить на все объекты вокруг поля. В п. 282 СанПиН 2.1.3684-21 для обработки с БАС расстояние до населённых пунктов составляет не менее 700 м, а отдельный абзац о постоянных медоносных пасеках сохраняет минимум 5 км. П. 286 запрещает обработку при обнаружении людей или домашних животных на участке и в пределах 700 м при подлёте БАС.

В модели поэтому три разных правила. Равенство 700 м и 5000 м удовлетворяет формулировке «не менее» п. 282. Выражение «в пределах 700 метров» п. 286 в этом примере принято включающим границу. Это явное консервативное допущение для алгоритма; перед применением на местности потребуются оценка погрешности координат и уточнение спорных границ.

На 17 проверках получено 17 ожидаемых результатов. Проверены точки на метр ближе порога, ровно на пороге и на метр дальше; человек внутри участка; отсутствующая геометрия; неполный список пасек; другая дата; неподдерживаемый вид работ; градусы вместо метров; самопересекающийся контур. Если нарушение уже найдено, а другая категория объектов неизвестна, найденное нарушение сохраняется вместе с признаком неполноты входов.

## Данные и метод

Все координаты синтетические. Поле представляет собой квадрат от 0 до 100 м по обеим осям. Объекты для граничных проверок размещены справа от него, напротив прямой стороны. Поэтому ожидаемое расстояние получается вручную как разность координат; оно задано в `cases.json` до запуска геометрического расчёта. Shapely вычисляет минимальное расстояние между участком и геометрией объекта. Для объекта внутри участка расстояние равно нулю.

Входы перечислены в `cases.json`, правила с привязкой к пунктам в `rules.json`, текст источника в `source.md`, код в `check.py`, результат в `results/results.json`. Метка полноты каталога в этих опытах задаётся составителем учебного набора. Способ проверить полноту реального каталога здесь не разработан. Наблюдение людей моделирует условие при подлёте; получение таких наблюдений автоматически не реализовано.

Дата 17.11.2026 обозначает зафиксированный снимок проверенного текста. Другие даты отклоняются: история редакций и определение применимости нормы по дате ещё не реализованы. Источник воспроизведён правовым порталом; в комплекте нет проверенного официального подписанного файла документа.

Пример показывает, что норму можно выразить отдельным условием, проверить на геометрии и объяснить результат через источник. Он не выполняет автоматическое извлечение норм, геокодирование и обработку настоящего участка. Проверены только названные категории объектов, а не весь перечень п. 282 и не все условия п. 286. Ветер, препарат и его регистрация, региональные ограничения, уведомления, режим воздушного пространства и остальные требования в расчёт не включены. Значение `no_conflict_in_example` означает отсутствие противоречия только в пределах этих трёх проверок; разрешение обработки или полёта не выдаётся.

## Повторение и вклад

Python 3.12 или новее. Из этой папки в отдельном окружении:

```powershell
python -m pip install -r requirements.txt
python check.py
```

При необходимости восстановить исходные учебные случаи: `python build_cases.py`. В проверенном запуске обработка правил и 17 случаев заняла 0,08 с. Это время данного расчёта, не оценка производительности будущего сервиса. Время подготовки материалов и токены не измерялись.

Формализация, код, учебные случаи и проверка выполнены Codex по поручению Димы 17.11.2026. Получение собственных данных и личный вклад Юры этим примером не подтверждаются. Для будущего продукта остаются проверка первоисточников, поддержка редакций, реальные каталоги и их полнота, геопривязка, извлечение остальных норм и испытания на реальных запросах.
